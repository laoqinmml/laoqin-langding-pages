# B2B 落地页结构：一页该怎么组织

落地页只回答四件事：**谁在看 → 你卖什么 → 凭什么信你 → 下一步做什么。**

## 先判断类型，再决定篇幅

| 类型 | 读者最关心 | 首屏该放 | 篇幅 |
| --- | --- | --- | --- |
| B2B 制造 / 代工询盘 | 能不能按我的要求做出来、多快、什么认证 | 一句话能力 + 产品实拍 + 询盘 CTA | 8–12 屏 |
| 机械设备 / 工业品 | 参数、产能、售后、案例 | 设备实拍 + 关键参数 + 要报价 | 8–12 屏 |
| 专业服务 / 咨询 | 你解决什么问题、做过谁 | 问题陈述 + 服务范围 + 预约 | 6–9 屏 |
| 产品发布 / 预售 | 新在哪、什么时候能买 | 产品名 + 唯一卖点 + 留资 | 5–8 屏 |
| 本地商家 | 在哪、营业时间、多少钱 | 地址 + 电话 + 服务清单 | 3–5 屏 |

## 默认区块顺序（B2B 制造 / 代工）

1. **导航**——4–6 项，最后一项是主 CTA 按钮（Build your brief / Get a quote）。不要放十几项。
2. **首屏**——一句话价值（做什么、给谁做、凭什么）+ 一处实拍或核心产品图 + 两个 CTA（主：要报价 / 要目录；次：WhatsApp 或邮箱）+ 一行信任锚（成立年份 / 年产能 / 认证）。
3. **信任条**——3–4 个能核实的数字：成立年份、年产能、认证编号、服务客户类型。**数字必须有来源**，没有就不写这一条。
4. **核心卖点**——3–5 条，每条一个标题 + 两行解释 + 一个具体事实（不是形容词）。
5. **产品 / 系列**——系列名 + 适用范围 + 关键规格；能链到详情就链。
6. **应用场景**——按客户的使用场合分（例如六种运动、五类工况），每个场景一张图一句话。
7. **能力与产能**——设备、产线、检测手段、交期范围。这一块决定采购敢不敢问。
8. **合作方式与流程**——OEM / ODM / 白标分别怎么合作，几步走完，每步客户要提供什么。
9. **资质认证**——ISO / CE / FDA 等，写清证书名和编号，能给图就给图。
10. **案例 / 客户**——**没有授权就不要放**。宁可整块砍掉，也不要编客户名。
11. **FAQ**——把销售每天被问的问题写进去：最小起订量、打样周期、付款方式、运输、质保。这一块最省询盘沟通成本。
12. **询盘表单**——表单字段越少越好；旁边给 WhatsApp / 邮箱（有些采购就是不发表单）。
13. **页脚**——公司名、地址（有才写）、邮箱、社媒、隐私说明、版权。

类型不同可以合并或删减区块，但顺序基本固定：**能力 → 信任 → 场景 → 合作方式 → 下一步**。不要一上来就堆参数表。

## 每块怎么写

- **标题写结论，不写话题。** 「八道工序，每片镜片都过光学检测」比「质量控制」强。
- **数字要落地。** 年产能、交期、检测项数、认证编号——有来源的就写，没来源的用定性表述并告诉用户。
- **一段只讲一件事。** 每段 2–4 行，长段落没人读。
- **避免形容词堆叠。** 「专业、可靠、领先」这类词出现三次以上就等于没写。
- **CTA 用动词 + 得到什么。** 「Get the catalog & factory proposal」比「Contact us」强。

## CTA 与表单策略

- 首屏最多两个 CTA：一个要资料（询盘表单），一个直接联系（WhatsApp / 邮箱）。
- WhatsApp 没号码就别放按钮，或者明确告诉用户这个按钮目前是空的（示例项目就是这么处理的）。
- 表单字段默认四到五个：姓名、邮箱、（公司）、国家、需求描述。字段越多，转化越低。
- 表单必须带蜜罐字段（对用户隐藏，机器人会填），前端做基本校验，提交后给明确反馈：成功 / 校验失败 / 网络失败。
- 收集归因字段（`utm_*` / `gclid` / `fbclid`）写进数据表，方便后面判断哪个渠道来的询盘值钱。
- 表单旁边写一句隐私说明（不群发、不转卖），这是 B2B 客户填表的心理门槛。

## 常见失败模式

1. 首屏全是公司历史，没有产品实拍，也没告诉人下一步做什么。
2. 通篇形容词，没有一个数字。
3. 一个页面塞 30 个规格参数，读者找不到重点。
4. 表单 12 个字段，还要求填公司规模和预算。
5. 没有 FAQ，销售每天回答同样的问题。
6. 联系方式只有一张表单，没有 WhatsApp / 邮箱。
7. 编造客户名、销量、获奖——一旦被发现有假，整个页面作废。
8. 手机上横向滚动、字号过小、按钮点不中。
