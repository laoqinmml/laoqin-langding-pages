# 多方案设计：让几版一眼看出不是一个模子

用于两种场景：**比稿**（客户要挑）和**用户拿不定主意**（你做几版给他看）。

## 一次只做一版

用户要三个方向，也一版一版做：做完一版、自审完，再开下一版。并行做三版的结果通常是三版都半成品。

一版一个目录：`v1-<代号>/`、`v2-<代号>/`……共享 `../assets/`，根目录放汇总 `index.html`。技术栈默认原生（`index.html` + `styles.css` + `app.js`），无构建步骤，双击就能开——这一阶段只为了让客户挑方向，正式站按主线第 3 步迁进 Astro。

## 方向从主题长出来

三个可用的轴，**每个方向至少要有两个轴和别的方向不重叠**：

- **调色板**——底色 + 唯一的强调色，其余为中性色。写 4–6 个具名 hex。
- **字体气质**——字族 + 角色（标题 / 正文 / 数字各用什么，可变字宽拉到多少）。
- **版式机制**——两栏操作台 / 全幅照片层叠 / 严格网格 + 描边 / 时间轴 / 规格卡，这类结构性的差异。

跨行业取形参考：

| 主题 | 可以借的设计语言 |
| --- | --- |
| 机械设备 | 工程蓝图：网格底纹、标注线、等宽数字 |
| 材料 / 化工 | 实验室：冷调纸白、样品卡、参数表 |
| 代工 / 白标 | 标识系统：扁平色块、2px 描边、方形网格 |
| 光学 / 精密 | 可变字宽大字 + 剖面示意 |
| 食品 / 包装 | 版画感插画 + 高饱和色块 |

判据：**把三个方向的名字盖住只看截图，应该认不出是同一批人做的。** 如果换掉主色后三版看起来是同一个模板，那就是没做出差异。

比稿多版本时**各版信息顺序要一致**（见 [landing-page-structure.md](landing-page-structure.md)），只有设计语言不同。否则客户比的是内容，不是设计。

## 要避开的「一眼假 AI」味

- 紫蓝渐变 + 玻璃拟态 + 圆角阴影卡片三件套
- 居中 Hero + 三列图标 + 渐变按钮的标准排版
- 每一段都是「小标题 + 一段话 + 三个特性」的同构节奏
- 无意义的装饰性 3D 球体、粒子背景
- 从 Figma 模板直接搬来的构图，一眼能认出模板出处

## 自审：每版做完跑一次

```bash
cd examples && python -m http.server 5173     # 单独窗口常驻
node examples/_tools/shots.mjs v3-pictogram 1440 900 "top" "#brief@100" "click:label[for=b-sport-ski]"
python examples/_tools/sheet.py examples/_tools/shots/s1.jpg examples/_tools/shots/v3-*.png 3
```

`shots.mjs` 会顺手打印 console 报错、4xx、页面高度、屏数、H1 数量、横向溢出——**先看这几行，再看图**。动作支持 `top`、`#id@偏移`、`y=像素`、`click:选择器`、`hover:选择器`、`mouse:x,y`。

`sheet.py` 把截图拼成联系表并缩到一半：**看画面只读这一张**，不要逐张读原图。一轮修改只重拍改过的那几屏；手机版放到电脑版定稿之后再量。

## 出图：最后做

页面先用占位色块或临时图做完，定稿后再统一出图：

```bash
IMG_API_KEY=xxx python examples/_tools/gen_images.py assets jobs.json
```

要点：提示词里把**比例写成数字**（否则容易画歪）；统一风格后缀让一批图看起来是一套；密钥只从环境变量读，不要写进 jobs JSON；出完压到 ≤ 1800 px / JPEG q82。图片是 AI 示意图这件事，要在交付说明里写明。

## 三套现成样例

`examples/` 里是三套跑通的样例（同一批产品事实、三种设计语言：浅色光学实验室 / 深钴蓝夜景 WebGL / 赛事标识系统）。写第一版之前翻一遍它们，比看说明快。

## 交付说明里必须写的

- 每个方向的调色板、字体、版式机制各是什么
- 事实来源（哪一条来自参考页哪一节）
- 哪些常规内容没放、为什么（通常是参考页没给联系方式或案例）
- 表单没接后端（如适用）、图片是 AI 示意图
- 哪些没验证：真机流畅度、Safari、关掉 WebGL 的兜底路径
