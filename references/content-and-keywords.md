# 持续出内容：关键词与页面扩张

落地页上线只是开始。客户要持续拿自然流量时才走这条路——**不要为了「看起来内容多」而批量灌水**。

## 关键词怎么进来

接受粘贴 CSV、Markdown 表格、Excel 导出、Search Console 导出，或用户直接口述。最低要求四个字段：

| 字段 | 说明 |
| --- | --- |
| 关键词 | 目标搜索词 |
| 语言 | 这篇文章面向的语言 |
| 国家 | 目标市场 |
| 想表达什么 | 用户希望这篇文章说清的卖点、工艺、场景或问题 |

可选：目标页面类型、与哪个产品的关系、目标客户、竞品 URL、要内链到哪些页、配图或视频需求。

## 每篇动笔前先交四样

1. **搜索需求分析**：搜这个词的人处在采购的哪一步，他真正想解决什么。
2. **SERP 竞品分析**：现有结果都在讲什么，哪块没人讲清楚。
3. **文章大纲**：H2/H3 结构与每节要点。
4. **信息增益点**：这篇比现有结果多给了什么（真实数据、工艺细节、判断标准、踩坑经验）。

第四点最关键：**没有信息增益就不要写**。同结构、同观点的文章只会增加维护成本。

## 写作规矩

- 事实仍然只用客户给过的来源；参数、认证、产能、交期不能编。
- 先给结论再给理由，段落短，每节一个小标题。
- 用客户询盘里的原话来写小标题——采购问什么，标题就写什么。
- 表格适合放规格、对比、选择建议；不要用表格堆形容词。
- 配图给建议（尺寸见 [images.md](images.md)），别在正文里插无意义的装饰图。

## 写完后检查

- [ ] 与站内已有文章、同批文章不重复（同义改写不算不重复）
- [ ] 至少两到三条站内链接：链到相关产品页 / 分类页 / 另一篇相关文章
- [ ] 文章本身被至少一个页面链到（分类页、相关文章、首页模块），**不能是孤岛**
- [ ] 给出配图建议与 alt 文案
- [ ] title / description / H1 唯一且互相不冲突

## 内链结构

```
首页 / 产品分类 / 博客分类
      └── 详情页 ──→ 相关详情页（横向内链）
              └── 询盘页（每篇都要有一个通向表单的入口）
```

每篇正文里放一次询盘入口（文字链接或 CTA 按钮），不要每段都放。

## 从哪找词（客户自己就能做的三件事）

1. 翻自己的询盘邮件，把客户反复问的问题抄进关键词表。
2. 在目标市场的搜索引擎里输入核心词，看自动补全和相关搜索。
3. Search Console 上线两三个月后，把「有曝光没点击」的词拉出来做专题。

## 发布节奏

- 先做 3–5 篇能覆盖核心采购疑问的（MOQ、交期、质量、付款、物流、认证），比一个月发 30 篇空文章有用。
- 每篇发布后进 sitemap，并在一次 Search Console 提交里带上。
- 三个月后看哪些词有曝光没点击，改 title 和 description，再决定要不要扩写。
